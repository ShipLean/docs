Set these variables in the ShipLean service environment. Values marked **Not set** have no documented default; leave them out unless you need that option. Keep passwords, tokens, and keys in your deployment's secret store. The examples use placeholders, not working credentials.

## Database

### `SHIPLEAN_DB_CONNECTION`

Connection string for the required PostgreSQL database.

- **Default:** None; required.
- **Example:** `Host=db;Database=shiplean;Username=shiplean;Password=<database-password>`
- **Set it when:** Always. Point it at the database used by this ShipLean instance.

### `SHIPLEAN_DB_MIGRATE`

Controls whether ShipLean applies its database schema and migrations at startup.

- **Default:** `true`.
- **Example:** `false`
- **Set it when:** Set to `false` only when you manage schema changes separately.

## First admin

### `SHIPLEAN_ADMIN_EMAIL`

Email for the first instance admin. With password sign-in, use it with `SHIPLEAN_ADMIN_PASSWORD`. With an identity proxy, the email alone is enough.

- **Default:** Not set.
- **Example:** `admin@example.com`
- **Set it when:** You are bootstrapping the first instance admin. Remove it after sign-in when you followed the quick start.

### `SHIPLEAN_ADMIN_PASSWORD`

Password used when creating or finding the first instance admin with password sign-in. In proxy mode it is ignored, with a warning.

- **Default:** Not set.
- **Example:** `<initial-admin-password>`
- **Set it when:** You are bootstrapping the first instance admin with email and password sign-in. Do not keep it in the environment after setup.

## Attachments and blob storage

### `SHIPLEAN_BLOB_ROOT`

Folder used for attachments and profile photos when neither blob connection is set.

- **Default:** `data/blobs` below the app folder; the Compose setup uses `/data/blobs` on a named volume.
- **Example:** `/data/blobs`
- **Set it when:** You use folder storage and need to choose its persistent path. For multiple instances, use Postgres or S3 instead.

### `SHIPLEAN_BLOB_DB_CONNECTION`

PostgreSQL connection string for storing attachments and profile photos in a database table. It may point to the same database as `SHIPLEAN_DB_CONNECTION` or a separate one. ShipLean creates the table at startup when `SHIPLEAN_DB_MIGRATE` is enabled.

- **Default:** Not set.
- **Example:** `Host=db;Database=shiplean;Username=shiplean;Password=<database-password>`
- **Set it when:** You want database-backed blobs, especially when multiple instances run or the app has no persistent disk.

### `SHIPLEAN_BLOB_S3_CONNECTION`

Connection settings for an S3 bucket. Separate `name=value` settings with semicolons. `bucket` is required; set `region` or `serviceUrl`; set both `accessKey` and `secretKey`, or leave both out to use the AWS default credentials chain. `forcePathStyle` and `prefix` are optional. The bucket must already exist.

- **Default:** Not set.
- **Example:** `bucket=shiplean;region=ap-southeast-1;prefix=prod/`
- **Set it when:** You want attachments and photos in AWS S3 or an S3-compatible service such as R2 or MinIO, especially for multiple instances or when app disk is not persistent.

ShipLean chooses the first configured store in this order: `SHIPLEAN_BLOB_S3_CONNECTION`, then `SHIPLEAN_BLOB_DB_CONNECTION`, then the folder at `SHIPLEAN_BLOB_ROOT`. Startup logs the selected store and reason with passwords and secret keys omitted. It warns when both connection settings are present. Changing stores does not move existing files; files remain in the old store.

### `SHIPLEAN_ATTACHMENT_MAX_BYTES`

Maximum size of one attachment accepted through uploads and imports, in bytes.

- **Default:** `26214400` (25 MiB).
- **Example:** `52428800` (50 MiB).
- **Set it when:** You need to allow a different maximum size for one file.

### `SHIPLEAN_ATTACHMENT_MAX_ITEM_BYTES`

Maximum total attachment bytes held by one work item, counting live files. Replaced files stop counting, but each file still has to meet `SHIPLEAN_ATTACHMENT_MAX_BYTES`.

- **Default:** `262144000` (250 MiB).
- **Example:** `524288000` (500 MiB).
- **Set it when:** You need a different total attachment allowance per work item.

## Reverse proxy

### `SHIPLEAN_TRUSTED_PROXIES`

Comma-separated addresses or CIDRs for the reverse proxy whose forwarded client address and scheme ShipLean trusts. Compose trusts its own network by default.

- **Default:** Compose trusts its own network; outside Compose, loopback is trusted by default.
- **Example:** `172.31.250.0/24,10.0.0.12`
- **Set it when:** Your proxy connects from an address outside the trusted defaults. Use the address ShipLean sees as the proxy peer.

### `SHIPLEAN_FORWARDED_FOR_HEADER`

Header name containing the original client address when your proxy sets its own forwarded-address header.

- **Default:** `X-Forwarded-For`.
- **Example:** `CF-Connecting-IP`
- **Set it when:** Your proxy uses a different header, such as Cloudflare's `CF-Connecting-IP`.

## Sign-in through an identity proxy

### `SHIPLEAN_AUTH_PROXY_TOKEN_HEADER`

Enables the recommended identity-proxy sign-in mode and names the request header carrying the proxy's signed JWT. ShipLean verifies the token on every request. Configure `SHIPLEAN_AUTH_PROXY_TOKEN_ISSUER` too.

- **Default:** Not set; email-and-password sign-in remains active.
- **Example:** `Cf-Access-Jwt-Assertion`
- **Set it when:** Your proxy forwards a signed identity token. Common header names are `X-Forwarded-Access-Token` (oauth2-proxy), `Cf-Access-Jwt-Assertion` (Cloudflare Access), and `X-Pomerium-Jwt-Assertion` (Pomerium). Use `Authorization` to read a Bearer token.

### `SHIPLEAN_AUTH_PROXY_TOKEN_ISSUER`

Expected `iss` value for the identity token. ShipLean obtains signing keys from the issuer's `/.well-known/openid-configuration` discovery document unless a JWKS URL is set.

- **Default:** Not set; required with `SHIPLEAN_AUTH_PROXY_TOKEN_HEADER`.
- **Example:** `https://login.example.com/`
- **Set it when:** You enable token-based proxy sign-in. Use an absolute HTTPS URL; HTTP is allowed only for loopback.

### `SHIPLEAN_AUTH_PROXY_TOKEN_JWKS_URL`

Overrides discovery with an explicit key-set URL for an issuer without a discovery document.

- **Default:** Not set; discovery is used.
- **Example:** `https://team.example.cloudflareaccess.com/cdn-cgi/access/certs`
- **Set it when:** Your identity provider requires a direct JWKS URL, such as Cloudflare Access. It follows the same URL rule as the issuer.

### `SHIPLEAN_AUTH_PROXY_TOKEN_AUDIENCE`

Expected audience claim in the signed identity token.

- **Default:** Not set; no audience value is configured.
- **Example:** `shiplean.example.com`
- **Set it when:** You want ShipLean to require a particular value in the token's `aud` claim.

### `SHIPLEAN_AUTH_PROXY_EMAIL_CLAIM`

Claim name holding the signed-in person's email address.

- **Default:** `email`.
- **Example:** `preferred_username`
- **Set it when:** Your identity provider stores email under a different claim name.

### `SHIPLEAN_AUTH_PROXY_NAME_CLAIM`

Claim name holding the person's display name. If the claim is missing, a new user's name is the part of their email before `@`.

- **Default:** `name`.
- **Example:** `display_name`
- **Set it when:** Your identity provider uses a different claim for a person's name.

### `SHIPLEAN_AUTH_PROXY_EMAIL_HEADER`

Enables proxy sign-in using an email header when the proxy sends no signed token. ShipLean trusts this header only from loopback and addresses in `SHIPLEAN_TRUSTED_PROXIES`. Do not set it together with `SHIPLEAN_AUTH_PROXY_TOKEN_HEADER`.

- **Default:** Not set; plain-header proxy sign-in is off.
- **Example:** `Remote-Email`
- **Set it when:** Your proxy provides a trusted email header, such as Authelia's `Remote-Email`, and only the proxy can reach ShipLean. A direct client that can set this header can act as any email.

### `SHIPLEAN_AUTH_PROXY_NAME_HEADER`

Optional header containing a display name in plain-header proxy mode.

- **Default:** Not set.
- **Example:** `Remote-Name`
- **Set it when:** You use `SHIPLEAN_AUTH_PROXY_EMAIL_HEADER` and your proxy also supplies a name.

### `SHIPLEAN_AUTH_PROXY_SIGN_OUT_URL`

Destination for the ShipLean sign-out action while proxy sign-in is active.

- **Default:** Not set; the sign-out action is hidden.
- **Example:** `/oauth2/sign_out`
- **Set it when:** You want sign-out to send the person to the proxy's sign-out route or another HTTP(S) destination.

## MCP gateway

### `SHIPLEAN_MCP_GATEWAY_EMAIL_HEADER`

Enables trusted-gateway identity for `/mcp` and names the request header carrying the caller's email. A request without a bearer token and with one non-blank header value acts as that person; a valid ShipLean bearer token continues to work.

- **Default:** Not set; `/mcp` accepts ShipLean agent bearer tokens and ignores this header.
- **Example:** `x-user-email`
- **Set it when:** A sidecar, policy proxy, or ingress writes this header and removes any client-supplied copy, and clients cannot reach `/mcp` directly. A client that can set it can act as any email. Project membership still limits board access.

## GitHub/GitLab integration

Environment integration settings are defaults. Saved settings under **Instance settings → Integrations** override `SHIPLEAN_GITHUB_TOKEN`, `SHIPLEAN_GITLAB_URL`, and `SHIPLEAN_GITLAB_TOKEN`. The GitHub API URL is environment-only. A saved GitLab URL uses its saved token rather than mixing in the environment token. Clearing the saved GitLab URL restores the environment pair. Tokens are sent only to HTTPS API addresses.

### `SHIPLEAN_GITHUB_TOKEN`

GitHub token that lets Feature pull-request and issue links show live titles and states, including for private repositories. Without it, only public repositories can be read.

- **Default:** Not set.
- **Example:** `<github-read-token>`
- **Set it when:** You want live link cards for private GitHub repositories. Provide a token that can read pull requests and issues.

### `SHIPLEAN_GITHUB_API_URL`

GitHub API base address. This value is configured by the environment and is not overridden in Instance settings.

- **Default:** `https://api.github.com`.
- **Example:** `https://github.example.com/api/v3`
- **Set it when:** You use GitHub Enterprise Server.

### `SHIPLEAN_GITLAB_URL`

GitLab host used to read merge-request and issue links. Links on other GitLab hosts remain ordinary page links. When unset, GitLab links are not read.

- **Default:** Not set.
- **Example:** `https://gitlab.example.com`
- **Set it when:** You want live link cards for a self-hosted or selected GitLab host.

### `SHIPLEAN_GITLAB_TOKEN`

GitLab token that can read merge requests and issues. It is used only with `SHIPLEAN_GITLAB_URL` and sent only when that URL is HTTPS.

- **Default:** Not set.
- **Example:** `<gitlab-read-token>`
- **Set it when:** You need live link cards from a private GitLab project. A saved GitLab URL in Instance settings uses its matching saved token instead.

## Webhooks

### `SHIPLEAN_GITHUB_WEBHOOK_SECRET`

Secret expected on GitHub webhook requests. Setting it enables `POST /api/webhooks/github`; otherwise that endpoint returns 404.

- **Default:** Not set; the endpoint is off.
- **Example:** `<github-webhook-secret>`
- **Set it when:** You configure the GitHub webhook so pull requests can link to work items, show their state, and close linked items on merge.

### `SHIPLEAN_GITLAB_WEBHOOK_SECRET`

Secret expected on GitLab webhook requests. Setting it enables `POST /api/webhooks/gitlab`; otherwise that endpoint returns 404.

- **Default:** Not set; the endpoint is off.
- **Example:** `<gitlab-webhook-secret>`
- **Set it when:** You configure the GitLab webhook so merge requests can link to work items, show their state, and close linked items on merge.

## Multiple instances (Redis)

### `SHIPLEAN_REDIS_CONNECTION`

StackExchange.Redis connection string. With multiple ShipLean instances, Redis carries the SignalR backplane plus shared presence and member-removal messages. The load balancer still needs sticky sessions so SignalR negotiate and WebSocket requests reach the same instance. Redis must be reachable when ShipLean starts.

- **Default:** Not set; real-time state remains in process.
- **Example:** `redis:6379,password=<redis-password>,channelPrefix=shiplean-prod`
- **Set it when:** You run more than one instance. If deployments share a Redis server, set a different `channelPrefix` for each; the default prefix is `shiplean`.

## Logging (Seq)

### `SHIPLEAN_SEQ_URL`

Seq server address to receive application logs in addition to the console.

- **Default:** Not set; Seq logging is off.
- **Example:** `http://seq:5341`
- **Set it when:** You want ShipLean logs sent to your Seq server.

### `SHIPLEAN_SEQ_API_KEY`

API key used to authenticate ShipLean's Seq log connection.

- **Default:** Not set.
- **Example:** `<seq-api-key>`
- **Set it when:** Your Seq server requires an API key. Keep it in a secret store.

## Jira import

### `SHIPLEAN_JIRA_ALLOW_LOCAL_ENDPOINTS`

Allows Jira import addresses that are local, and permits plain HTTP to any host. HTTP sends the token without encryption.

- **Default:** Off (`false`).
- **Example:** `true`
- **Set it when:** Jira is on your own network and you need to import from a local endpoint. Leave it off otherwise.

## Search

### `SHIPLEAN_EMBEDDINGS`

Controls semantic search. When a model is loaded, `on` ranks by meaning as well as words; `off` keeps search lexical.

- **Default:** `on`.
- **Example:** `off`
- **Set it when:** You want lexical-only search, for example when semantic embeddings are unavailable.

### `SHIPLEAN_EMBEDDINGS_MODEL_PATH`

Folder containing the embedding model files. The published image sets this to `/app/models/multilingual-e5-small`.

- **Default:** `/app/models/multilingual-e5-small` in the published image.
- **Example:** `/app/models/multilingual-e5-small`
- **Set it when:** You run the published image with a model mounted at a different path. An unreadable or missing model leaves search lexical and `/health` reports why.

### `SHIPLEAN_SEARCH_CHUNK_CHARS`

Length in characters of each text chunk created for indexing.

- **Default:** `1200`.
- **Example:** `1200`
- **Set it when:** You need to adjust the amount of text indexed as one chunk.

### `SHIPLEAN_SEARCH_CHUNK_OVERLAP`

Number of neighbouring characters repeated between indexed text chunks.

- **Default:** `150`.
- **Example:** `150`
- **Set it when:** You need to adjust how much context adjacent chunks share.

### `SHIPLEAN_SEARCH_CUTOFF`

Lowest semantic similarity score, from 0 to 1, accepted as a meaning match.

- **Default:** `0.55`.
- **Example:** `0.55`
- **Set it when:** You need to tune the semantic match threshold.

### `SHIPLEAN_SEARCH_TOP_PER_LIST`

Maximum number of results kept from each ranked search list before merging.

- **Default:** `100`.
- **Example:** `100`
- **Set it when:** You need to change how many candidates are considered from each list.

### `SHIPLEAN_SEARCH_RRF_K`

Reciprocal-rank-fusion constant used to merge ranked result lists.

- **Default:** `60`.
- **Example:** `60`
- **Set it when:** You need to tune how separate ranked lists are combined.

### `SHIPLEAN_SEARCH_BATCH`

Number of texts embedded in each model call.

- **Default:** `32`.
- **Example:** `32`
- **Set it when:** You need to change how many texts are sent per embedding call.

### `SHIPLEAN_SEARCH_THREADS`

Number of ONNX Runtime intra-op threads used for embedding.

- **Default:** `1`.
- **Example:** `1`
- **Set it when:** You need to change embedding thread use on your host.

### `SHIPLEAN_SEARCH_FIRST_PASS_SECONDS`

Delay in seconds before the background indexer's first pass after startup.

- **Default:** `20`.
- **Example:** `20`
- **Set it when:** You need to change when the first indexing pass starts.

### `SHIPLEAN_SEARCH_INTERVAL_SECONDS`

Number of seconds between background indexer passes.

- **Default:** `60`.
- **Example:** `60`
- **Set it when:** You need to change the interval between indexing passes.

## Compose-only

### `SHIPLEAN_PORT`

Host port published for the ShipLean web app by the Compose setup.

- **Default:** `8080` in the product Compose file.
- **Example:** `8081`
- **Set it when:** Host port 8080 is already in use or you want a different local port.

### `SHIPLEAN_PG_PORT`

Host port published for PostgreSQL by the Compose setup.

- **Default:** `5432` in the product Compose file.
- **Example:** `5433`
- **Set it when:** Host port 5432 is already in use or you want a different local port.

The Compose table also has `POSTGRES_PASSWORD`, which sets PostgreSQL's password. It is not a `SHIPLEAN_*` variable.
