This walkthrough takes you from a blank workspace to a small sprint plan. You need permission to create projects. Use your team's real names, or follow the example.

## Create the project

1. Open **New project** from the project switcher.
2. Enter a name and a unique key of two to four letters, such as `ACME`. Work item keys use this prefix, for example `ACME-1`.
3. Choose whether to copy settings from an existing project, add member email addresses, and choose working days. You can leave the optional choices at their defaults.
4. Select **Create project**.

<Shot name="guide-first-project-create" alt="New project form with fields for project name and key." />

See [New project](/ui/new-project/) for the fields and project settings.

## Add an Epic and two Features

1. Open **Backlogs**, then **Epics**, and add an Epic for a broad area, for example **Onboarding**.
2. Open **Backlogs**, then **Features**. Add two Features under that Epic, for example **Invite teammates** and **Explain project access**. Each Feature can have a goal that describes the outcome.
3. Use the item's parent field to choose the Epic. Features can also contain Features when you need another level.

<Shot name="guide-first-project-epics" alt="Epics backlog showing the Onboarding Epic and its Feature count." />

See [Work items](/ui/work-items/) for creating and editing items.

## Add Stories and estimates

1. Open **Backlogs**, then **Stories**. Add a few small Stories under either Feature.
2. Describe the result each Story delivers. Add a story-point estimate if your team estimates work in points.
3. Keep the items in the default starting state until work begins. The default states are **New**, **Active**, **Resolved**, **Closed**, and **Removed**. States are grouped into workflow categories. The default states do not include blocked or parked. To record that work is blocked or parked, use a status line or a tag.

<Shot name="guide-first-project-stories" alt="Stories backlog with a few Stories under their parent Features." />

See [Stories backlog](/ui/backlogs/) for ranking and filtering.

## Review the board

Open **Boards**, then **Stories**. The board columns show the states configured for Stories and Bugs. Move a card when its state changes. Open **Settings** if your team needs different columns or WIP limits.

<Shot name="guide-first-project-board" alt="Stories board showing the new project work arranged in state columns." />

See [Boards](/ui/boards/) and [Board settings](/ui/board-settings/) for column mappings.

## Create a sprint and plan work

1. Open **Sprints** and create a sprint with a name, start date and end date. Add a goal if useful.
2. If your team uses capacity, open the sprint's **Capacity** page and enter the team velocity and each person's days available.
3. Open **Backlogs**, then **Stories**, and choose **Planning**. Move a few Stories into the sprint section. Compare the committed points with the forecast before you finish.

<Shot name="guide-first-project-sprint" alt="Sprint planning view with Stories placed in a sprint section." />

Continue with [Sprint planning and capacity](/ui/planning/) or [Run a Scrum sprint](/start/guides/scrum-sprint/).
