The Feature timeline is a Gantt chart of how a Feature was delivered. It is built after the fact from the state history of the Feature's tasks. Nobody draws it or enters dates. Use it to see where the time went: what ran in parallel, what waited, and what set the finish date.

The address is `/p/:key/items/:itemKey/timeline`, where `:itemKey` is the Feature's key.

## Open the timeline

Open a Feature and find the **Timeline** section. It shows the four [key dates](#key-dates) and an **Open timeline** link. Select the link to open the page. Select **Back to** the Feature's key at the top of the page to return.

The timeline is for desktop screens. On a narrow or touch screen, 900 px wide or less, the **Open timeline** link is hidden, and the phone app has no timeline. The Feature page still shows the key dates there. See [ShipLean on your phone](/ui/mobile/).

## Key dates

The header and the Feature page's **Timeline** section show the same four dates, with the gap between each pair. The Planned date also says what was planned, such as "Plan captured: 4 stories and bugs, 9 tasks", or "First stories created (no captured plan)" when no plan was captured:

- **Added.** When the Feature was created, and by whom.
- **Planned.** When a plan was captured, or when the first Story or Bug was added if no plan was captured.
- **Execution started.** When the first task that has a recorded start moved to an in-progress state.
- **Finished.** When the Feature moved to a completed state. A Feature that was reopened has no finish date until it is completed again.

A date that has not happened yet reads **Not yet**. While the Feature is running, the gap to **Finished** is dashed and reads "so far". The gaps are not drawn to scale. The execution gap, from **Execution started** to **Finished**, is the one in colour.

## Header figures

Above the key dates, four figures sum up the Feature. A caption beside them gives the finish date for a finished Feature, such as "Finished Wed 21 Oct. Bars run from Active to Resolved, from each task's state history." For a running Feature it gives the time the chart was drawn, such as "Open bars run to now, Sat 24 Oct, 14:00."

- **Lead time.** Days from Added to Finished, or to now while the Feature runs.
- **Execution.** Calendar days of execution, so far while it runs.
- **Tasks started.** How many tasks have started, out of all tasks, and how many were closed with no start.
- **Reviews.** How many review rounds were logged, and how many asked for changes.

## Read the chart

The chart has one row for each Story or Bug and each task, whether or not it has started. The left column heads read **STORY · TASK** and **TOOK**. Each row has a type badge (S for Story, T for Task, B for Bug), the assignee's avatar with an AI chip for an agent, and a dot after the title when the task is on the critical path. **TOOK** is how long the item took, or **No start** when it has no start recorded.

The axis shows calendar days in the server's time zone (UTC in the published image), not the zone in your [profile](/ui/profile/). Sprint names run across the top and weekends are shaded. In **Fit** zoom the axis is labelled by week, with the date of each Monday. A running Feature has a blue dashed **Now** line.

An item that has not started is a row with no bar. A not-started task sits under its Story. A not-started Story or Bug comes after the started ones.

### Bars

A bar is one task. It starts when the task first moved to an in-progress state and ends when it last moved to Resolved, or to Closed if it was never resolved. The bar is drawn from state history only. A task that is still being worked on has no end yet and runs to now.

A label after each bar gives its length, such as **2.5 h** or **4.3 days**.

A dashed outline **diamond** marks a task that was closed with no start recorded. It sits at the moment of closing and has no length, because ShipLean cannot say when the work began. It is labelled **Closed, no start recorded**.

### Story brackets

A blue bracket with an end tick at each side spans a Story or Bug, with its length after it. It starts when its first task starts. It ends when its last task ends, and only when every task under it has ended. Until then the bracket has no end.

Removed Stories, Bugs and tasks are left out.

### Review dots

A dot after a bar is one review round on that task. Green is **Approved** and amber is **Changes asked**. A thin dashed line joins the dots to the bar. A review that came before the bar ended sits on the bar. Selecting it selects the task.

Review rounds come from the `log_review` tool, which agents call to record a round on a task. Reviews are recorded for tasks only. A task with no recorded rounds has no dots. See the [tool reference](/agents/tools/).

### Arrows

With **Dependencies** on, arrows join one task to the task that waited on it.

- A solid grey arrow means the first task had to finish before the second started. It comes from a link between the two, or from the order of the plan's waves when the second task has no link arrow of its own.
- A dashed red arrow means a task blocked another one part-way. It comes from a **Blocked by** link where the second task had already started before the first ended.

### Waits

A label on an arrow, such as **22.8 h wait** or **1.9 days wait**, is how long the later task waited after the earlier one ended. A wait under 12 hours has no label. An overlap has none either.

## Toolbar

Every setting is kept in the address, so you can share a link to a particular view. Only settings that differ from the defaults appear in it.

- **Group.** Choose how rows are arranged. **Stories** shows a bracket with its tasks beneath it. **People** shows one group per assignee, with **Unassigned** last. **Tasks** shows a flat list ordered by start time.
- **Zoom.** **Fit** squeezes the whole range into the available width, with room kept at the right for the last labels, and labels each week. **Days** gives each day a fixed width and labels it with the weekday, and the chart scrolls sideways.
- **Dependencies.** Shows or hides the arrows, waits and the critical path outline. It is on by default.
- **Critical path.** See below. It is on by default but can only be turned on once the Feature is finished.
- **Chart** and **JSON for agents.** Switch between the chart and the [JSON view](#json-view).

The legend at the right of the toolbar names the bar and dot colours.

## Critical path

The critical path is the chain of tasks that set the finish date. ShipLean starts from the task that ended last. It then follows each arrow back to the task that released it, as long as that task ended no more than an hour after the next one started. A task that blocked a task on the chain is added to it.

Tasks on the path get a dark outline, and the arrows between them are drawn heavier. With **Critical path** on, bars and brackets off the path are faded. A Story or Bug is on the path when any of its tasks is. The **Critical path** control is disabled until the Feature is done. A running Feature has no critical path, because its finish is not known. Its tooltip reads "Shows once the Feature is Done."

## The rail

The right rail changes with what you select. Select a bar, bracket or diamond to select it. Select a key in the rail to jump to that item. Select the **✕** or press **Esc** to clear the selection.

With nothing selected, the rail shows **Reading the chart**, a short legend of bars, brackets, diamonds, review dots, arrows and the critical path. When some items have not begun, it also lists them under **Not started**.

With a task selected, the rail shows:

- Its key, its title and the **Assignee**, with an **Agent** chip for an agent.
- **Story**, the Story it belongs to, as a link.
- **Active** and **Resolved**, when it started and ended.
- **Took**, its length, with a **Critical path** pill if it is on the path.
- **Reviewed**, the time of its first review. It is left out when there is none.
- **Last commit**, when its last commit was made.
- **History.** Each state it was in, when it entered it and how long it stayed, with a coloured dot for each state. Blocked time appears as **Blocked**.
- **Reviews.** Each round with a dot for its verdict, who gave it, when, and the note.- **Waited on.** The tasks it waited for, with the wait.
- **Held up.** The tasks that waited for it. A task that blocked it is marked "(blocked it)".

An **Open** button, such as **Open SHIP-192**, opens the task. A back link, **Reading the chart**, clears the selection.

With a Story or Bug selected, the rail shows its dates and its tasks.

## JSON view

Choose **JSON for agents** to see exactly what an agent receives from the `feature_timeline` tool for this Feature, with a **Copy** button. Times are in UTC.

The page and the tool use the same data. The JSON view lets you check what an agent is told before you rely on it, and compare it with the chart. The rail changes to two sections. **The call** shows the `feature_timeline` call that returns this view. **How the chart maps to it** shows which part of the chart each field draws:

- `bars`: one entry per task, with its start, end, history periods and reviews.
- `stories`: the brackets, each Story or Bug with its task keys.
- `edges`: the arrows, with from, to, kind, source and wait.
- `critical_path`: the keys on the critical path, in order.
- `key_dates`: added, planned, execution started and finished.

See the [tool reference](/agents/tools/) for `feature_timeline` and `log_review`.

## Limits

- The chart comes from state history. A task moved straight to Closed shows as a diamond, and a task that never left New is not drawn.
- Waits and arrows need links between items or a captured plan with waves. Without them the chart shows bars and brackets only.
- Review dots exist only for rounds recorded with `log_review`.
- The timeline is for Features. An Epic, Story, Bug or Task has none.
- It is for desktop screens. See [ShipLean on your phone](/ui/mobile/).
