Open an item from a backlog, board or link to see its fields, description, child tasks and history. Changes in the item form stay as a draft until you choose **Save**. Comments, task states and attachments save on their own.

## Address

- Item: `/p/:key/items/:itemKey`.
- Attachment: `/p/:key/items/:itemKey/attachments/:attachmentId`.
- You can also open an item in a modal over a project screen by adding `?item=:itemKey` to that screen's address.

## Edit fields and the description

Edit the title and choose **Save** when you are ready. The fields strip has State, Assignee, Points, Priority, Parent and Tags. Stories, Bugs, Action items and Tasks also have a Sprint field. A Story has an Acceptance criteria checklist. A Bug has Severity and Repro steps. Priority describes when you want to fix a Bug. Severity describes how much it affects people.

Choose a value from a field menu, or edit the title or Markdown section. A changed-field list appears beside the Save status. Choose **Save** to write those draft changes as a revision, or **Discard** to restore the last saved values. If you leave with an unsaved draft, ShipLean asks whether to stay or leave.

For Description or Repro steps, choose **Edit** to open the Markdown toolbar. Use the toolbar for formatting such as bold text, lists, links, and code. Choose **View** to read the rendered Markdown. Pasted images become attachments. If your draft includes an external image, ShipLean asks before saving it.

## Action items

An Action item is a work item raised from retrospective points. It sits at the same level as a Story or Bug and can go in a sprint. Its points count toward sprint committed and completed figures, burndown, velocity and forecast. Its parent is a Feature or none. It has four states: New, Active, Closed and Removed, with no Resolved state.

An Action item raised from retro points starts in New with no sprint. Pulling it into a sprint is the approval to work on it. An Action item created with **+ Add story or bug** on the Taskboard goes into that Taskboard's sprint. On a Feature board it goes under the Feature with no sprint. To raise one from retro points, see [Raising an action item](/ui/sprint-retro/#raising-an-action-item). Action items are not a Jira import target.

An Action item page has a **Why this exists** section. It quotes each retro point the item covers, with a link back to the point. It has a theme menu and a **Type of fix** menu, and **+ Add points** adds more points to the item. An Action item made without retro points has no such section.

<Shot name="ui-work-items-action-item" alt="An Action item's page with the Why this exists section quoting its retro points, a theme menu, a Type of fix menu and the + Add points button." />

## Read the retrospective

The **Retrospectives** section appears on a Story, Bug, Action item or Feature that has at least one retro. On a Story, Bug or Action item it sits below the description and above Tasks. On a Feature it sits after the Stories and bugs. A Task has no such section. An item with no retro shows no section and no empty message. The section is read-only.

Each row is one retro, newest first. A row shows the author and, under **Logged**, when the retro was logged. It also shows a count for each of Went well, Not in the plan, Went badly and Can be improved. The **To decide** column counts the points that still need a decision. The **Decided** column shows how many of those points have a decision, as a bar and a count, or "nothing to decide" when the retro has no such points. A retro from an agent shows the agent's name, and an unfinished retro shows "partial" beside the author. If ShipLean cannot load the retros, the section shows an error message.

Choose a row to open the item's page under [Retrospectives](/ui/retrospectives/), filtered to that retro, where you read its points and decide them. **All retros for this item** opens the same page without the filter. Agents add retros with `log_retrospective`. See [Finishing and learning](/work/done/).

<Shot name="ui-work-items-retrospective" alt="The Retrospectives section of a Story with one retro row. The row shows the author, when it was logged, one point each under Went badly and Can be improved, two points to decide and a decided count of 0 of 2." />

## Add and update tasks

Use the **Tasks** section on a Story or Bug to break the work into child Tasks. Choose **+ Task**, enter a title, and add it. A Task is its own work item. Its state control saves immediately. Choose the title or key to open its full details. The count shows how many child Tasks are complete.

An Action item with no Tasks shows no Tasks section. One that has Tasks lists them, with no **+ Task** button. To add a Task under an Action item, pull the Action item into a sprint first, then use **+ Task** on its row in the [Taskboard](/ui/taskboard/). An Action item with a Feature parent also has a row with **+ Task** on the [Feature board](/ui/feature-board/), with no sprint needed.

## Discuss the work

Use **Discussion** to leave a comment or mention a project member with `@`. Comments save when you post, separately from the item form. Use **Ctrl+Enter** or **⌘+Enter** to post. You can edit your own comments. A project admin can archive another member's comment. Any project member can mark a comment as superseded, which keeps it in the discussion with a strike-through.

On a Feature the same comment stream is called **Log**, and it lists newest entries first. Entries from an agent are marked as agent activity.

## Decisions and questions

The **Decisions and questions** section appears on Stories and Features. It shows decisions and questions recorded by an agent, with numbered labels. A decision includes a recommended answer and may include alternatives; the owner can confirm it, choose an alternative, enter another answer, or withdraw it. A question can be open-ended or offer up to six short answers to choose from. The owner answers on the item. Decision changes appear in the item's history; an answer to a question is posted as a Markdown comment in Discussion. An agent that asked a question should continue with independent work or hand back; it should not wait for a reply. The next agent to pick up the item reads the owner's answer. See [agent scopes](/agents/scopes/) for the related MCP tools.

## Link work and code

Use **Links** to add a relationship to another work item or a URL. Add, edit, or remove a link in the form, then choose **Save** to keep the change. A linked pull or merge request on a Story, Bug, or Task can show a state badge when a provider webhook reports it. The badge reflects the latest reported state. See [GitHub and GitLab links](/start/integrations/#connect-github-and-gitlab-link-cards) for provider setup.

Feature links use a separate section. That section saves immediately and can show GitHub or GitLab issue, pull-request, or merge-request details. See [Features and the Feature editor](/ui/features/).

## Attach files and read history

Use the side rail to upload an attachment or open one already there. Markdown attachments open on their own attachment page. Images open in a preview. Other files download. You can remove an attachment from the rail. Attachments stay with the item and can hold research notes, plans, and supporting files.

On the attachment page, **Edit** opens the file in the same editor as a description. **Save** replaces the file under the same name, and the old copy is kept as a soft-deleted version. A fenced `mermaid` code block, such as a sequence diagram, is drawn as a diagram in attachments, descriptions and comments.

The **History** section lists saved revisions with who changed the item, when, and the fields that changed. The header also shows who created and last changed the item, and the current revision. Discussion comments are separate from revision history.

<Shot name="ui-work-items-history" alt="Revision history beside an item's attachments." />

## Resolve a save conflict

If another person saves first, your Save does not overwrite their revision. ShipLean keeps your draft and shows a conflict banner. The banner shows who saved first, what changed in their revision, your unsaved fields, and any fields you both changed.

- Choose **Reload theirs** to load the newer revision and drop your draft.
- Choose **Re-apply mine** to put your draft on top of the newer revision. Your value wins for a field you both changed. Then choose **Save** to write the result as the next revision.

<Shot name="ui-work-items-conflict" alt="Save conflict comparing another person's changes with the current draft and offering Reload theirs or Re-apply mine." />

## Change state or remove an item

Choose **State** and select one of the states configured for that work item type in project settings. State categories determine how the project treats the item. To remove an item from active work, select a state in the **Removed** category. The item is hidden from normal backlogs. ShipLean does not hard-delete it.

## Options and shortcuts

- **Ctrl+S** or **⌘+S** saves the item form. You can also choose **Save**.
- **Ctrl+Enter** or **⌘+Enter** posts a comment.
- A new Task's state saves immediately. Other field edits in the main form need **Save**.
